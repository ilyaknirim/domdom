# Политика безопасности

## 🔒 Сообщение об уязвимостях

Безопасность нашего проекта - наш высший приоритет. Если вы обнаружили уязвимость в системе безопасности, пожалуйста, сообщите нам об этом.

### Как сообщить

**НЕ создавайте публичные Issue для проблем безопасности.**

Вместо этого, отправьте email на: **security@example.com** (замените на свой email)

Включите в сообщение:
- Описание уязвимости
- Шаги для воспроизведения
- Потенциальное влияние
- Возможные решения (если есть)

### Что ожидать

- Мы подтвердим получение вашего сообщения в течение 48 часов
- Мы предоставим более детальный ответ в течение 7 дней
- Мы будем держать вас в курсе процесса исправления

### Политика раскрытия

- Пожалуйста, дайте нам разумное время для исправления уязвимости до публичного раскрытия
- Мы публично признаем ваш вклад после исправления (если вы хотите)

## 🛡️ Реализованные меры безопасности

### Backend
- ✅ **Аутентификация через Telegram** - проверка подписи WebApp
- ✅ **JWT токены** для API запросов
- ✅ **Rate limiting** - защита от DDoS атак
- ✅ **Input validation** - валидация всех входных данных
- ✅ **SQL injection protection** - использование Prisma ORM
- ✅ **CORS** настроен только для доверенных источников
- ✅ **Password hashing** - bcrypt с солью
- ✅ **Secure headers** - helmet.js middleware
- ✅ **XSS protection** - санитизация пользовательского контента
- ✅ **CSRF protection** - токены для форм

### Frontend
- ✅ **Безопасное хранение токенов** - не используем localStorage для чувствительных данных
- ✅ **HTTPS only** - все запросы через защищенное соединение
- ✅ **Content Security Policy** - защита от XSS
- ✅ **Sanitized inputs** - очистка всех пользовательских вводов

### База данных
- ✅ **Шифрование паролей** - bcrypt
- ✅ **Prepared statements** - через Prisma
- ✅ **Регулярные бекапы**
- ✅ **Ограниченные права доступа**

### Infrastructure
- ✅ **Environment variables** - чувствительные данные в .env
- ✅ **Secrets management** - не храним секреты в коде
- ✅ **Docker security** - non-root пользователи
- ✅ **SSL/TLS** - HTTPS для всех соединений

## 🔐 Рекомендации по безопасности для деплоя

### 1. Переменные окружения
```bash
# НИКОГДА не используйте эти значения в production:
JWT_SECRET=change-this-in-production
DATABASE_PASSWORD=postgres

# Используйте сложные случайные строки:
JWT_SECRET=$(openssl rand -base64 32)
DATABASE_PASSWORD=$(openssl rand -base64 32)
```

### 2. База данных
- Используйте сильные пароли (минимум 20 символов)
- Ограничьте доступ по IP
- Включите SSL соединения
- Регулярно обновляйте PostgreSQL
- Делайте backup каждый день

### 3. API Rate Limiting
```typescript
// Настройте лимиты в зависимости от endpoint
const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 минут
  max: 5, // 5 попыток входа
});

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 100, // 100 запросов
});
```

### 4. Firewall правила
```bash
# Разрешить только необходимые порты
ufw allow 22/tcp   # SSH
ufw allow 80/tcp   # HTTP
ufw allow 443/tcp  # HTTPS
ufw enable
```

### 5. Мониторинг
- Настройте алерты на подозрительную активность
- Логируйте все неудачные попытки входа
- Мониторьте необычные паттерны трафика
- Используйте IDS/IPS системы

### 6. Обновления
```bash
# Регулярно обновляйте зависимости
npm audit
npm audit fix

# Проверяйте известные уязвимости
npm audit --production
```

### 7. Telegram Bot Token
- **НИКОГДА** не коммитьте токен в git
- Используйте разные токены для dev/staging/prod
- Регулярно ротируйте токены
- Ограничьте IP через @BotFather если возможно

### 8. Резервное копирование
```bash
# Автоматический backup базы данных
0 2 * * * pg_dump $DATABASE_URL > /backups/db_$(date +\%Y\%m\%d).sql
```

## ⚠️ Важные предупреждения

### ❌ НЕ ДЕЛАЙТЕ ЭТО:

```typescript
// ❌ Прямое использование пользовательского ввода
app.get('/user/:id', (req, res) => {
  const query = `SELECT * FROM users WHERE id = ${req.params.id}`;
  // SQL INJECTION!
});

// ❌ Хранение паролей в открытом виде
const user = {
  password: req.body.password // НЕТ!
};

// ❌ Использование eval()
eval(userInput); // ОПАСНО!

// ❌ Передача чувствительных данных в URL
const url = `/api/payment?creditCard=${cardNumber}`; // НЕТ!
```

### ✅ ДЕЛАЙТЕ ТАК:

```typescript
// ✅ Используйте ORM
const user = await prisma.user.findUnique({
  where: { id: req.params.id }
});

// ✅ Хешируйте пароли
const hashedPassword = await bcrypt.hash(password, 10);

// ✅ Валидируйте ввод
const schema = Joi.object({
  email: Joi.string().email().required(),
  phone: Joi.string().pattern(/^\+972[0-9]{9}$/)
});

// ✅ Используйте POST для чувствительных данных
app.post('/api/payment', validateAuth, async (req, res) => {
  // Данные в теле запроса, защищенном HTTPS

```

## 📋 Security Checklist

Перед деплоем в production:

- [ ] Все секреты в environment variables
- [ ] JWT_SECRET изменен на случайную строку
- [ ] Database пароль сложный (20+ символов)
- [ ] HTTPS настроен с валидным сертификатом
- [ ] Rate limiting включен
- [ ] CORS настроен только на ваш домен
- [ ] Firewall правила настроены
- [ ] Backup базы данных автоматизирован
- [ ] Логирование настроено
- [ ] Мониторинг ошибок настроен (Sentry)
- [ ] npm audit проверен (0 уязвимостей)
- [ ] Зависимости обновлены
- [ ] Тесты безопасности пройдены
- [ ] Документация по безопасности прочитана командой
- [ ] Plan B на случай взлома

## 🚨 В случае инцидента

1. **Немедленно:**
   - Изолируйте скомпрометированную систему
   - Смените все пароли и токены
   - Уведомите пользователей если нужно

2. **Анализ:**
   - Соберите логи
   - Определите масштаб утечки
   - Найдите точку входа

3. **Восстановление:**
   - Исправьте уязвимость
   - Восстановите из бекапа если нужно
   - Проведите аудит безопасности

4. **Пост-мортем:**
   - Документируйте инцидент
   - Обновите процедуры безопасности
   - Обучите команду
